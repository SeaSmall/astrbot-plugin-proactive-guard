# AstrBot 主动消息门禁 + 每日定时人格消息（proactive_guard）

一个 [AstrBot](https://github.com/AstrBotDevs/AstrBot)（4.x）插件，做两件事：

1. **🚪 主动消息门禁**：阻止「本插件之外」的 AI 主动发言。只要用户没有发消息，任何 AI 对话的**生成与发送都会被拦截**——包括 AstrBot 内置「主动型 Agent」、定时主动任务、陪伴类插件等。用户正常发消息聊天完全不受影响。
2. **💬 每日定时人格消息**：每天在**后台静默**预生成「**明天**」的 5~10 条消息，随机分配到 **07:00~23:00** 之间的不重复时间点，由 AI 根据**人格设定**和每个时间点的场景撰写各不相同的内容，存入内部存储；**到点自动发送该条并删除**，跨天自动把预生成的「明天」计划提升为「今天」，日复一日。全程不向用户发送任何报备/确认消息。
3. **🧠 记忆库**：插件自己维护一份记忆——定时把近期真实对话交给 AI 总结成要点（称呼、身份、正在做的事、情绪、约定），存进插件存储；写消息时把这份记忆喂给 AI，让主动消息能**接着聊过的话题往下说**，而不是每天凭空寒暄。
4. **🤖 子代理生成**：一条消息不再由单次 LLM 调用「一把梭」，而是拆成**规划 → 并行写手 → 审校**三段各司其职的调用。某个时间点写砸了不会拖垮整天，每个写手只看到自己那一条的内容要点，不会串味。

> 灵感来源：机器人"突然冒出一句话"（如 QQ 官方适配器日志里的 `Agent 使用工具: ['send_message_to_user']`）——那是 AstrBot 的主动型 Agent/定时任务在主动聊天。本插件把这类行为统一收编：**只有本插件允许的人格消息能在用户没说话时发出去**。

## 🧩 工作原理

### 门禁（拦截层）

插件激活时，在 `Context.send_message`（AstrBot 唯一的**主动发送**入口）上安装一层拦截：

- 非本插件的主动发送 → **直接丢弃**，并在日志记录（`[proactive_guard] 已拦截非白名单主动消息 -> ...（来源模块: ...）`），不打扰用户；
- 以下情况放行：
  - **本插件自己**发送（每日人格消息，带内部标记）；
  - **白名单插件**（配置 `allow_senders`，如 `daily_digest`）；
  - **用户最近活跃的会话**（默认 30 分钟内用户发过消息 → 视为正常对话回复，可配 `active_window_minutes`）；
- 可选 `strict_mode`：只放行本插件，其余一律拦截。

同时插件会**自动暂停** AstrBot 内置的「主动型 Agent」定时任务（`cron_manager` 中的 `active_agent` 任务，**可逆**，不会删除；在面板可恢复）。用户正常消息的回复走的是另一条发送链路，**不受影响**。

### 每日计划（生成层）

1. **预生成「明天」**：计划以「明天」为目标日期提前生成（`gen_time` 默认每天 06:00 触发；若计划缺失，**任意时刻**都会自动补种，20 分钟节流）；
2. 在 `window_start ~ window_end`（默认 07:00~23:00）内随机抽取 5~10 个**互不相同**的时间点（`msg_count_min/max` 可配）；
3. 调用 AstrBot 当前 LLM，按**当前人格设定**（自动读取 AstrBot 的「人格」设置，无需单独配置）和每个时间点的场景写一条消息，输出 JSON；
4. 存入插件 KV 存储（**双槽位**：`daily_plan` = 今天的计划、`daily_plan_next` = 明天的预生成，含日期，重启不丢）；
5. **跨天提升**：0 点后自动把 `daily_plan_next`（date 已变为今天）提升为 `daily_plan`，并预生成新的「明天」；
6. 每**分钟**检查一次：只从 `daily_plan`（date == 今天）派发——到点 → 发送 → **删除该时间点**；错过未发（设备休眠）→ 30 分钟补偿窗口内补发，超窗丢弃；过期计划静默丢弃；
7. **记忆写入**：发送的同时把消息写入该会话的 LLM 对话历史（assistant 角色，可配置 `record_to_history`），模型后续回复时知道机器人主动说过什么，不会出现「被动输出与主动输出」记忆断层。

> 💡 因此：手动清理掉「明天」的定时消息后，重载插件会**立即重新生成「明天」**，绝不会生成「后天」。

### 记忆库（记忆层）

1. **定时总结**：`memory_cron`（默认每天 03:00）触发，把每个目标会话最近的 `memory_turns` 条对话交给 AI 总结；
2. **滚动更新**：每次把「上一轮的旧摘要 + 这一轮的新对话」一起交给 AI **重写**，而不是把新内容追加到旧摘要后面——所以记忆长度不会随天数无限膨胀，始终控制在 `memory_max_chars` 以内；
3. **存进插件存储**（KV key = `memory_store`），结构 `{"updated": "...", "items": [{"umo","summary","updated"}]}`，重启不丢；
4. **生成时读取**：写消息前先取记忆，注入到规划代理与写手代理的提示词里，让主动消息延续聊过的话题；
5. **三级降级**：记忆库有内容 → 直接用；记忆库为空 → **当场就地总结一次**建库；总结也失败 → 按 `memory_raw_fallback` 决定是否退回「未经总结的原始对话」（更杂但不会没得用）；
6. 指令 `/记忆` 随时查看当前记忆库，`/刷新记忆` 立即重新总结一次。

> 💡 记忆与「记忆写入」是两件事：**记忆写入**（第 7 步）是把机器人**主动说过的话**追加进对话历史，避免模型不知道自己说过什么；**记忆库**是把**用户说过的话**总结成要点，供写消息时参考。两者互补。

### 子代理生成（v1.1.0）

关闭 `subagent_enabled` 时为 v1.0.x 的单次调用行为；打开时（默认）走三段流水线：

1. **规划代理**：只看日期 + 人格 + 记忆 + 时间点列表，为每个时间点出一句**内容要点**（不写正文），输出 `[{"time":"07:35","point":"要点"}]`；
2. **写手代理**：**每个时间点一次独立调用**，只拿到自己那条的要点和记忆，写一条 20~60 字的消息。多个写手按 `subagent_concurrency`（默认 3）限流并行；`subagent_parallel=false` 则串行；
3. **审校代理**：拿到全天草稿，统一语气、去重、修正场景错位。它**只能改文案**——若返回的条数与时间点对不上（AI 擅自增删），直接丢弃审校结果、回退写手原稿，保证不会少发或错时。

任一环节失败都不会让整天丢失：规划失败 → 回退单次调用；部分写手失败 → 保留成功的那几条；审校失败 → 用写手原稿。
> ⚠️ 「规划失败 → 回退单次调用」这条兜底**从 v1.1.1 才真正生效**：此前流水线失败时只打一条 warning 就返回空结果，
> 调用方直接报「计划生成失败」，回退并未发生。详见 [CHANGELOG.md](CHANGELOG.md)。

## 📦 安装

1. AstrBot WebUI →「插件」→「安装插件」→「通过 Git 地址安装」
2. 输入：`https://github.com/SeaSmall/astrbot-plugin-proactive-guard`
3. 启用插件，在配置面板按需修改（时间窗口、目标会话等）

> 要求 **AstrBot 4.x**。

## ⚙️ 配置说明

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | 总开关 |
| `block_proactive` | bool | `true` | 门禁开关：拦截非本插件的 AI 主动发言 |
| `strict_mode` | bool | `false` | 严格模式：只放行本插件，连"用户最近活跃会话"也拦截 |
| `active_window_minutes` | int | `30` | 活跃窗口（分钟）：用户此窗口内发过消息的会话放行（视为正常对话） |
| `allow_senders` | text | `daily_digest` | 主动发送白名单：插件模块名关键词，每行一个（**默认放行 `daily_digest` 日报**，可增删；改其它非空值即完全覆盖默认） |
| `pause_active_agent_jobs` | bool | `true` | 启用时自动暂停 AstrBot 内置主动型 Agent 任务（可恢复） |
| `gen_time` | string | `0 6 * * *` | 每日计划生成时间（cron，默认每天 06:00）：确保「明天」计划已预生成；计划缺失时任意时刻自动补种（20 分钟节流） |
| `timezone` | string | `Asia/Shanghai` | 定时任务时区（IANA 时区名）。**必须与部署机器实际时区一致**，否则 cron 会在错误时间触发（如默认 UTC 时 `0 6 * * *` 会按 UTC 6 点跑） |
| `message_prompt` | text | 见默认值 | 写消息提示词模板（`{persona}` 自动替换为 **AstrBot 当前人格设定**，`{date} {time_list} {count}` 自动替换）。**仅当 `subagent_enabled` 关闭时使用**；开启时由内置的规划/写手/审校三段提示词接管 |
| `subagent_enabled` | bool | `true` | 用子代理流水线生成（规划 → 并行写手 → 审校）。关闭则回退为 v1.0.x 的单次 LLM 调用 |
| `subagent_parallel` | bool | `true` | 多个写手代理是否并行 |
| `subagent_concurrency` | int | `3` | 写手代理最大并发数 |
| `subagent_review` | bool | `true` | 是否启用审校代理（统一语气、去重、修场景错位） |
| `memory_enabled` | bool | `true` | 记忆库总开关 |
| `memory_cron` | string | `0 3 * * *` | 记忆总结时间（cron，默认每天 03:00） |
| `memory_turns` | int | `20` | 每次总结取该会话最近多少条对话 |
| `memory_max_chars` | int | `1500` | 记忆摘要长度上限（**下限 200**，配小于 200 也按 200 算） |
| `memory_raw_fallback` | bool | `true` | 记忆库为空且总结失败时，是否退回「未经总结的原始对话」兜底 |
| `msg_count_min` / `msg_count_max` | int | `5` / `10` | 每日消息条数范围 |
| `window_start` / `window_end` | string | `07:00` / `23:00` | 消息时间窗口 |
| `missed_grace_minutes` | int | `30` | 错过补发窗口（分钟），超窗丢弃 |
| `record_to_history` | bool | `true` | 把主动发送的人格消息写入该会话的 LLM 对话历史（assistant 角色），让模型后续回复时知道机器人主动说过什么（避免记忆断层）；关闭则不写入 |
| `target_sessions` | text | 空 | 发送目标会话（unified_msg_origin，每行一个）；留空自动选择 |
| `only_private` | bool | `true` | 未指定目标时：仅发私聊会话，不打扰群聊 |

## 🎮 指令（用户主动触发，可选）

| 指令 | 说明 |
| --- | --- |
| `/今日计划` | 查看今日待发送的消息计划 + 明日预生成摘要 |
| `/重建今日计划` | 立即在后台重新生成明天的计划（今天窗口未结束且今天计划缺失时也补一份今天的） |
| `/记忆` | 查看记忆库当前内容（最后更新时间 + 每个会话的摘要） |
| `/刷新记忆` | 立即重新总结一次记忆（后台执行，完成后可再用 `/记忆` 查看） |

## ❓ 常见问题

**Q：装上门禁后，之前的"突然冒话"还会出现吗？**
不会。主动型 Agent 任务会被自动暂停，且即使任何插件/AI 尝试主动发送，也会被门禁拦截（日志可见）。

**Q：写消息用的人格是哪来的？**
无需单独配置——插件自动读取 **AstrBot 当前默认人格**（`服务提供商 → 人格` 里设置的默认人格）的设定文本；如果 AstrBot 未设置任何人格，则使用内置的温和默认人设兜底。

**Q：记忆库和 AstrBot 自带的对话历史有什么区别？**
对话历史是**原始流水账**（每句话都留着，占用 context 且噪声大）；记忆库是**AI 提炼过的要点**（称呼、身份、正在做的事、情绪、偏好、约定），更短、更聚焦，而且会滚动重写、长度受控。插件在生成时会优先用记忆库。

**Q：记忆会泄露隐私吗？**
记忆库只存在**你自己的 AstrBot 数据目录里**（插件 KV 存储），不会外传；内容由你自己配置的 LLM 生成。不需要时把 `memory_enabled` 关掉即可，已有记忆可用 `/记忆` 查看。

**Q：为什么一天的消息有时条数不齐？**
正常不会。审校代理如果擅自增删条数，插件会丢弃审校结果、回退写手原稿；某个写手失败也只是少那一条，其余照常发送。若日志出现「计划生成失败」，说明整批 LLM 输出都无法解析，会在下一个检查周期重试。

**Q：会不会误伤正常聊天？**
不会。用户发消息→机器人回复走的是正常链路，不经过门禁；只有"用户没发消息时的主动发送"才被拦截。同一会话 30 分钟内有用户消息时，AI 的回复/发送也正常放行。

**Q：机器人错过到点的消息怎么办？**
30 分钟（`missed_grace_minutes`）内自动补发，超过则丢弃该条，不堆积。

**Q：手动清理了明天的计划，重载后为什么重新生成的是「明天」而不是「后天」？**
v1.0.1 起计划以「明天」为目标日期提前预生成（`daily_plan_next`），清理后任意时刻重载都会立即重新生成**明天**，绝不生成后天。

**Q：想恢复 AstrBot 自带的主动型能力？**
在 AstrBot 面板恢复被暂停的主动任务，并关闭本插件的 `pause_active_agent_jobs` 或直接禁用本插件门禁（`block_proactive`）。
